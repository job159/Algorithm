# 卡爾曼濾波器：六個觀念，一個一個來

> **一句話總結**：卡爾曼濾波只做一件事 ——
> 手上有兩個都不準的答案（**模型的預測**、**感測器的量測**），照「**誰比較準**」加權平均。
> 每一秒重複「預測（變不確定）→ 量測 → 融合（變確定）」，就能把吵雜的量測變成又穩又準的估計，
> 甚至估出根本量不到的東西（例如速度）。

這份文件是 `kalman_lessons_pyqt6.py`（六堂互動課）的文字版。
**建議順序**：先跑互動課、一章一章看 → 再看這份文件的對應章節 → 最後讀 `kalman_2d.py`（工程版，STEP 1～13）。

```bash
python kalman_lessons_pyqt6.py
```

整套教材的顏色固定：**藍 = 預測**（模型說的）、**紅 = 量測**（感測器說的）、**綠 = 融合後的估計**（卡爾曼的答案）、**灰 = 真值**（現實中看不到，只為了教學）。

## 第 1 章　兩個都不準的資訊，怎麼合併？

**情境**：你想知道車子在哪。

- 模型「預測」：車子在 **10 m**，誤差大約 **±2 m**
- GPS「量測」：車子在 **14 m**，誤差大約 **±4 m**

該信誰？**兩個都信，但信多少要看誰比較準。**

```
   機率
    │            融合 10.8（±1.79）← 最窄最高：最確定
    │               ▲
    │          ▄▀▀▀▀▀▄   預測 10（±2）
    │        ▄▀  ▄▀▀▄ ▀▄
    │      ▄▀  ▄▀    ▀▄ ▀▄▄▄▄▄▄▄▄▄   GPS 14（±4）← 最寬最矮：最不確定
    │ ▄▄▄▀▀▄▄▀▀        ▀▀▄▄▄       ▀▀▀▄▄▄▄
    └────────────────────────────────────────── 位置
              10   10.8           14
```

**三行算完：**

| 步驟 | 公式 | 代入 |
|---|---|---|
| ① 權重 K | K = σ預測² ÷ (σ預測² + σGPS²) | 2² ÷ (2² + 4²) = **0.20** |
| ② 融合位置 | 預測 + K × (GPS − 預測) | 10 + 0.20 × 4 = **10.8 m** |
| ③ 融合後的不確定 | √(1 − K) × σ預測 | √0.8 × 2 = **±1.79 m** |

**三個結論**（互動課裡可以親手驗證）：
1. **誰比較準，結果就靠近誰**：GPS 越準，K 越接近 1；兩個一樣準，K = 0.5、剛好在中間。
2. **合併後一定比兩者都更確定**：±1.79 比 ±2 和 ±4 都小。多一份資訊，絕不會變更糊塗。
3. **被拉過去多少只看 K、不看距離**：GPS 就算離譜到 100 m 外，也照樣被拉 20% → 第 5 章要加「閘門」擋掉。

> 💡 第 1 章就是卡爾曼濾波的全部核心。後面五章都只是「在什麼時候、用什麼數字」重複這一步。

## 第 2 章　讓時間動起來：預測 → 量測 → 融合

真實世界是一直在動的。車子大約以 **1 m/s** 前進，GPS 每秒給一次位置（±2.5 m）。每一秒都做三件事：

```
        ┌──────────── 每一秒重複 ────────────┐
        ▼                                     │
   ① 預測：x⁻ = x + 車速 × 1 秒               │
            不確定變胖：P⁻ = P + Q            │
        ▼                                     │
   ② 量測：收到 GPS z（±2.5）                 │
        ▼                                     │
   ③ 融合：就是第 1 章！                      │
            K = P⁻ ÷ (P⁻ + R)                 │
            x = x⁻ + K × (z − x⁻)             │
            不確定變瘦：P = (1 − K) × P⁻ ─────┘
```

**為什麼預測會「變胖」？** 模型說「車速 1 m/s」，但司機的油門會有點鬆緊。往前推一秒，就多了一點不確定 —— 這個「每秒多出來的不確定」就是 **Q**。

**跟著互動課手算前四秒**（GPS 雜訊 R = 2.5² = 6.25，Q = 0.5）：

| 秒 | ① 預測 x⁻（±σ） | ② GPS z | ③ K | ③ 融合 x（±σ） | 真實位置 |
|---|---|---|---|---|---|
| 0 | — | −0.12 | — | **−0.12**（±2.50）← 第一筆直接當起點 | 0.50 |
| 1 | −0.12 + 1 = 0.88（±2.60） | 1.56 | 0.52 | **1.24**（±1.80） | 1.07 |
| 2 | 1.24 + 1 = 2.24（±1.94） | 3.45 | 0.38 | **2.69**（±1.53） | 1.87 |
| 3 | 2.69 + 1 = 3.69（±1.69） | 1.63 | 0.31 | **3.05**（±1.40） | 3.37 |
| 4 | 3.05 + 1 = 4.05（±1.57） | 3.91 | 0.28 | **4.01**（±1.33） | 4.91 |
| … | | | **0.25**（穩定） | （±1.24）| |

**重點觀察**：
- **不確定度會「呼吸」**：每秒預測時漲一點（±1.24 → ±1.43）、融合時掉一點（±1.43 → ±1.24），幾秒後就穩定成固定的鋸齒。
- **K 會自己收斂**：一開始 0.52（還不太信自己），幾秒後固定在 **0.25**。K 是算出來的，不是調出來的。
- 整段 20 秒：直接用 GPS 誤差 **2.32 m**，卡爾曼 **0.82 m**。

## 第 3 章　Q 與 R：相信模型，還是相信感測器？

| 參數 | 白話 | 調大會怎樣 |
|---|---|---|
| **Q** | 模型每秒可能錯多少 | 越不信模型 → K 變大 → 跟得快、但比較抖 |
| **R** | 感測器有多吵 | 越不信感測器 → K 變小 → 很平滑、但比較慢 |

互動課第 3 章故意讓司機「先加速、再放慢」，而模型一直以為車速是 1 m/s（模型是錯的）。三種設定的結果：

| 設定 | 穩態 K | 落後（整段偏一邊） | 抖動（上下跳） | 總誤差 |
|---|---|---|---|---|
| 太相信模型（√Q = 0.05） | 0.03 | **5.45 m** | 0.56 m | 5.73 m |
| 太相信 GPS（√R = 0.15） | 0.96 | 0.60 m | **2.55 m** | 2.64 m |
| 剛剛好（√Q = 1.71，電腦掃出來的） | 0.49 | 1.06 m | 1.29 m | **1.76 m** |
| （直接用 GPS） | — | — | — | 2.76 m |

**三個結論**：
1. **太相信模型 = 很平滑但跟不上**：模型一錯（司機加速），估計就整段落後。
2. **太相信感測器 = 跟得上但很抖**：幾乎照抄 GPS，濾波等於沒做。
3. **只有比例 Q : R 重要**：Q、R 同時放大 10 倍，K 和結果完全不變。

**工程上怎麼定？**
- **R**：直接看感測器規格書（GPS ±5 m → R = 25）。或讓感測器靜止，量一段資料算變異數。
- **Q**：不要亂調，從物理推：「目標最猛會怎麼加速？」→ σ<sub>a</sub>，再用運動學換算成 Q（`kalman_2d.py` STEP 4）。
- **驗收**：現場沒有真值時，看 **NIS 的長期平均**（STEP 13）：應該 ≈ 量測維度（2D 位置 = 2）。太大 = 濾波器太自信（Q 或 R 設太小）；太小 = 太保守。

## 第 4 章　量不到的速度，怎麼估出來？

GPS 只量位置，但卡爾曼能同時估出**速度**。這是卡爾曼最神奇、也最重要的一點。

把狀態寫成兩個數：**[位置, 速度]**，畫在一張平面上，不確定度就變成一個**橢圓**：

```
  速度                        速度                         速度
   │   ┃                       │      ╱╱                     │      ╱╱
   │   ┃   一開始：             │    ╱╱   預測後：            │    ░▓▓░   融合後：
   │   ┃   位置大概知道         │  ╱╱     被「斜切」          │    ░▓▓░   紅帶切掉位置不對的點
   │   ┃   速度完全不知道       │╱╱       位置和速度綁在一起   │    ░▓▓░   → 速度也被切窄了！
   └───╂──── 位置               └────────── 位置              └───░▓▓░─── 位置
                                                                   紅帶 = GPS 說的位置
```

**為什麼預測會「斜切」？** 預測就是「位置 += 速度 × 1 秒」：
- 速度大的那些可能性，往右跑得遠；速度小的，跑得近。
- 整團可能性被斜切成斜的橢圓 → **位置和速度產生了關聯**（互動課裡相關係數高達 0.93）。

**為什麼量位置能修正速度？** GPS 的紅帶只限制位置；但橢圓是斜的，**「位置不對」的那些點，剛好就是「速度太大或太小」的點**。切掉它們，速度範圍也跟著變窄。

互動課的數字（真實速度 2 m/s，速度從沒量過）：

| 秒 | 速度估計 | 速度不確定 σ |
|---|---|---|
| 0 | 0（先亂猜） | 5.00 m/s |
| 1 | 0.72 | **2.46** ← 第一次融合就少一半 |
| 2 | 2.37 | 1.37 |
| 3 | 2.87 | 0.90 |
| 8 | 2.18 | 0.42 |

> 💡 如果預測不會讓橢圓變斜（位置和速度沒關聯），量位置就**完全無法**修正速度。「預測」不只是往前推，它建立了變數之間的關係。

## 第 5 章　工程版：2D 追蹤 + 閘門 + 訊號遺失

真正的產品（車載導航、無人機、雷達追蹤）= 前四章，再加上：

**① 2D：x、y 兩個方向一起做。** 狀態 = [x, y, vx, vy]，量測 = [x, y]。數學上就是把 1D 的數字換成矩陣（第 6 章），觀念完全不變。

**② 閘門（Gating）：太離譜的量測直接丟掉。**
第 1 章說過：被拉多少只看 K、不看距離。GPS 偶爾會因為多路徑反射跳到 40 m 外，照樣融合就會把估計拉歪。
所以融合前先檢查：「以目前的不確定度，這筆量測合理嗎？」

```
   NIS = (量測 − 預測)² ÷ (兩者不確定度相加)      ← 2D 時是 yᵀ S⁻¹ y
   NIS > 9.21  → 判為跳點，丟掉，這一秒只用預測
```

9.21 是「2 自由度卡方分布的 99% 分位」：正常的量測只有 1% 機率超過它。

**③ 訊號遺失：沒有量測就只預測。** 進隧道收不到 GPS → 跳過融合，只做預測。不確定度每秒變大（橢圓膨脹）；出隧道後第一筆 GPS 會被大大相信（K 很大），一下子拉回來。

**再加兩個「不會壞」的保險**（`kalman_2d.py`）：
- **Joseph 形式**更新 P：數值上永遠保持對稱、正定，跑幾萬步也不會壞（STEP 11）。
- **保險絲**：連續被閘門擋 3 次 → 比較可能是自己跟丟了，用最新量測重新開始。

`python kalman_2d.py` 的結果（60 秒、3 筆跳點、一段隧道）：

| 方法 | 位置誤差 RMSE |
|---|---|
| 直接用 GPS（含跳點） | 11.70 m |
| 卡爾曼，沒有閘門 | 7.15 m |
| **卡爾曼，有閘門（工程版）** | **5.52 m**，3 筆跳點全部擋下 |

## 第 6 章　把直覺翻成公式

公式沒有新東西 —— 每一行都是前面看過的一個動作：

| 你看到的 | 一維寫法 | 矩陣寫法 | `kalman_2d.py` |
|---|---|---|---|
| 預測：照模型往前推 | x⁻ = x + v·dt | x⁻ = F x | STEP 2、7 |
| 預測變胖 | P⁻ = P + Q | P⁻ = F P Fᵀ + Q | STEP 4、7 |
| 量測跟預測差多少 | y = z − x⁻ | y = z − H x⁻ | STEP 3、8 |
| 兩個不確定加起來 | S = P⁻ + R | S = H P⁻ Hᵀ + R | STEP 5、8 |
| 權重：誰比較準 | K = P⁻ ÷ (P⁻ + R) | K = P⁻ Hᵀ S⁻¹ | STEP 10 |
| 融合 | x = x⁻ + K·y | x = x⁻ + K y | STEP 11 |
| 融合變瘦 | P = (1 − K)·P⁻ | P = (I − KH) P⁻ (I − KH)ᵀ + K R Kᵀ | STEP 11 |
| 閘門 | \|y\| > 3√S 就丟 | yᵀ S⁻¹ y > 9.21 就丟 | STEP 9 |
| 遺失 | 沒有 z → 只預測 | 同左 | STEP 12 |

**四個矩陣各是什麼？**

| 矩陣 | 意思 | 對應的章節 |
|---|---|---|
| **F** | 運動模型「位置 += 速度 × dt」 | 第 4 章把橢圓斜切的就是它 |
| **H** | 量測模型「GPS 只量位置」 | 從狀態裡挑出位置那兩格 |
| **Q** | 模型每秒可能錯多少 | 第 3 章左邊的滑桿 |
| **R** | 感測器有多吵 | 第 3 章右邊的滑桿 |

```python
# 整個卡爾曼濾波器（工程版的骨架；完整版見 kalman_2d.py）
def kalman_step(x, P, z, F, Q, H, R, gate=9.21):
    x = F @ x                                  # 預測
    P = F @ P @ F.T + Q                        # 預測變胖
    if z is None:                              # 遺失：只預測
        return x, P
    y = z - H @ x                              # 量測跟預測差多少
    S = H @ P @ H.T + R                        # 兩個不確定加起來
    if y @ np.linalg.solve(S, y) > gate:       # 閘門：太離譜就丟
        return x, P
    K = np.linalg.solve(S, H @ P).T            # 權重（用 solve，不直接求反矩陣）
    x = x + K @ y                              # 融合
    I_KH = np.eye(len(x)) - K @ H
    P = I_KH @ P @ I_KH.T + K @ R @ K.T        # 融合變瘦（Joseph 形式）
    return x, P
```

## 常見的坑

| 坑 | 症狀 | 解法 |
|---|---|---|
| **單位不一致** | 結果爆掉或完全不動 | Q、R、P 全部用同一套單位（m、s），R 是「變異數」= σ² |
| **R 設太小** | 估計跟著雜訊抖、閘門一直誤擋 | R 用規格書或實測；NIS 長期平均應 ≈ 量測維度 |
| **Q 設太小** | 目標一轉彎就跟丟、閘門把正確量測擋掉 | Q 從「最大合理加速度」推，不要用 0 |
| **dt 寫死** | 取樣不穩時越跑越歪 | 每一步用實際時間差重算 F、Q |
| **初始化亂給** | 前幾秒亂跳 | 位置用第一筆量測、速度給 0 但不確定度給很大 |
| **P 不對稱** | 跑久了出現 NaN | Joseph 形式 + 每步 P = (P + Pᵀ)/2 |
| **直接求反矩陣** | 數值不穩 | 用 `np.linalg.solve` |
| **沒有閘門** | 一個跳點就把估計拉歪 | NIS 閘門 + 連續被擋時重新初始化 |

## 延伸：下一步學什麼

| 想解決的問題 | 方法 |
|---|---|
| 運動或量測是非線性的（例如雷達量距離 + 角度） | **EKF**（擴展卡爾曼）：每步在當下線性化 |
| 非線性很強、不想算偏微分 | **UKF**（無跡卡爾曼）：用幾個代表點穿過非線性 |

| 事後分析（離線、可以看未來） | **RTS 平滑器**：跑完再倒著修正一次，更準 |
| 只要固定增益、MCU 很省 | **α-β 濾波**（`filters/` 第 4 章）= 穩態卡爾曼 |

### 最後濃縮成三句話
1. **核心**：預測讓不確定變大，量測帶來新資訊，融合照「誰比較準」加權平均，讓不確定變小。
2. **調參**：Q、R 決定要相信模型還是感測器，它們的比例決定 K；太信模型會落後，太信感測器會抖。
3. **魔法與工程**：預測讓位置和速度產生關聯，所以只量位置也能估出速度；再加上閘門與遺失處理，就能上路。
