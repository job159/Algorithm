# 二維卡爾曼濾波器（工程用）：設計思路 與 一步一步的推導（白話詳解）

> **一句話總結**：卡爾曼濾波器 = 「**預測**」和「**量測**」兩個都不準的資訊，
> 依「**誰比較準**」給權重做加權平均。權重 K 不是亂調的，是從兩邊的不確定度（P 與 R）算出來的；
> 融合後的結果比任何一邊都準，而且還能順便把**根本沒有感測器在量的速度**「推」出來。

這份文件搭配兩支程式一起看最有感：
- `kalman_2d.py`：工程用函式庫 + 命令列測試（程式碼就是照本文 STEP 1～13 的順序寫的）
- `kalman_pyqt6_step.py`：逐步動畫，每個時刻拆成 7 個子步驟，一次只走「一行公式」

## 一、先搞懂：要解決什麼問題

追蹤一台在平面上移動的目標（車、無人機、雷達上的光點）。手上只有一個會報位置的感測器（GPS / 雷達），而它：

| 麻煩 | 長什麼樣子 | 本專案模擬 |
|---|---|---|
| **有雜訊** | 每一筆位置都在真值附近亂跳 | 高斯雜訊 σ = 5 m |
| **偶爾大跳點** | 訊號被大樓反射（多路徑），突然差幾十公尺 | 3 筆，跳 ~40 m |
| **有時收不到** | 進隧道、封包遺失 | k = 38～43 連續 6 筆沒有 |
| **速度根本量不到** | 感測器只給位置 | 速度要自己推 |

```
   真值（看不到）：  ─────────────╮
                                  ╰──────────────►（直線 → 右轉 90° → 加速）
   量測（拿得到）：  ·  ·· ·  ✕ · ·  ·  · ✕··  ··   ·   [隧道：沒資料]   · ·✕ · ·
                               ↑ 多路徑跳點
```

**最直覺的做法為什麼不行？**
- 直接相信量測 → 位置誤差就是感測器誤差（本例 RMSE 11.7 m，含跳點）。
- 速度用相鄰兩筆相減 `(z_k − z_{k−1}) / dt` → 雜訊被放大 √2/dt 倍，本例速度 RMSE **17.6 m/s**（目標本身才跑 6～15 m/s！），完全不能用。
- 移動平均 → 會落後、遇到跳點會被拉歪、也沒辦法處理「這一筆收不到」。

> 👉 我們需要一個方法：**知道目標大概怎麼動（模型）**，又**懂得評估每筆量測該信幾分**，還能**誠實說出自己有多不確定**。這就是卡爾曼濾波器。

本專案最終成績（`python kalman_2d.py`，seed = 7）：

| 方法 | 位置 RMSE | 速度 RMSE |
|---|---|---|
| 原始量測（含跳點） | 11.70 m | — |
| 相鄰量測差分 | — | 17.57 m/s |
| 卡爾曼（無閘門） | 7.15 m | 2.19 m/s |
| **卡爾曼（工程版，有閘門）** | **5.52 m** | **1.89 m/s** |

## 二、直覺：兩個都不準的資訊，怎麼合成一個更準的

### 兩個情報來源
1. **預測**：「上一秒在 (100, 50)、速度 (5, 0) → 這一秒**應該**在 (105, 50)」。靠的是運動模型，但目標可能偷偷加速、轉彎 → 不準。
2. **量測**：感測器說「我量到 (108, 48)」。但感測器有雜訊 → 也不準。

### 加權平均，權重 = 誰比較準
```
     預測 105 ± 4 m                量測 108 ± 5 m
        │◄────────── 落差 3 m ──────────►│
        │                                │
        └─────► 融合：105 + K × 3        K = 4² / (4² + 5²) = 0.39
                    = 106.2 ± 3.1 m      ← 比兩邊都準！
```
- **K（卡爾曼增益）** = 這次要「往量測方向走幾成」。
- 預測越不準 → K 越接近 1（聽量測）；量測越不準 → K 越接近 0（聽預測）。
- 融合後的不確定度 **一定比兩邊都小**：兩個獨立的資訊加起來，總是比單一個多知道一點。

### 一直循環：預測 → 更新 → 預測 → 更新 …
```
        ┌──────────────── 預測（時間往前走，越來越不確定：P 變大）────────────────┐
        │                                                                         ▼
   [ x, P ]                                                                  [ x⁻, P⁻ ]
        ▲                                                                         │
        └──────────────── 更新（收到量測，變確定：P 變小）◄──────────── 量測 z ───┘
```
動畫裡看得到：**橘色虛線橢圓（預測）一定比上一刻大，藍色實線橢圓（更新後）一定比橘色小。**

## 三、先用 1D 手算一次（看懂 K）

情境：一台**停著**的車，真實位置 10 m。GPS 每秒量一次，σ = 2 m → **R = 4**。
模型：「車大致不動」，但允許每秒有一點漂移 → **Q = 1**。一開始完全不知道車在哪 → 亂猜 x = 0，但 **P = 100**（「我不知道」= 大 P）。

1D 版的五行公式：
```
預測：  x⁻ = x            P⁻ = P + Q
增益：  K  = P⁻ / (P⁻ + R)
更新：  x  = x⁻ + K·(z − x⁻)        P = (1 − K)·P⁻
```

| k | 量測 z | P⁻ = P + Q | K = P⁻/(P⁻+R) | 落差 y = z − x⁻ | x = x⁻ + K·y | P = (1−K)P⁻ | 1σ = √P |
|---|---|---|---|---|---|---|---|
| 0 | — | — | — | — | 0（亂猜） | 100 | 10 m |
| 1 | 10.8 | 101.00 | **0.962** | +10.80 | 10.39 | 3.85 | 1.96 m |
| 2 | 9.6 | 4.85 | **0.548** | −0.79 | 9.96 | 2.19 | 1.48 m |
| 3 | 10.9 | 3.19 | **0.444** | +0.94 | 10.38 | 1.78 | 1.33 m |
| 4 | 10.3 | 2.78 | **0.410** | −0.08 | 10.34 | 1.64 | 1.28 m |
| 5 | 9.8 | 2.64 | **0.397** | −0.54 | 10.13 | 1.59 | 1.26 m |
| ∞ | | 2.56 | **0.390** | | | 1.56 | 1.25 m |

**重點觀察：**
- **第 1 步 K = 0.96**：一開始完全不知道（P⁻ = 101 ≫ R = 4）→ 幾乎全聽量測，一步就跳到 10.39。這就是「初始化給大 P」的好處。
- **K 一路收斂到 0.39**（穩態）：之後每筆量測只聽 39%，其餘 61% 聽預測 → 雜訊被平均掉。
- **1σ 從 10 m 降到 1.25 m，比 GPS 本身的 2 m 還準。** 這就是「融合比任何一邊都準」。
- 假設第 6 筆突然量到 **30**（跳點）：y = 19.9、S = P⁻ + R = 6.6 → NIS = y²/S = **59.9**，遠超過 1 自由度卡方 99% 的門檻 6.63 → 判為離群值、不更新。這就是第四章 STEP 9 的閘門。

> 2D 只是把「數字」換成「矩陣」：P 變 4×4、K 變 4×2、除法變成乘 S⁻¹。**意義完全一樣**。

## 四、推到 2D：工程師的設計順序 STEP 1～13

工程師寫濾波器的順序**不是先寫公式**，而是：先定義問題 → 定模型 → 定雜訊 → 才寫演算法 → 最後加防呆與監控。`kalman_2d.py` 就是照這個順序寫的，每一段都有對應的 STEP 註解。

### STEP 1　定義問題：要估計什麼？量得到什麼？
```
狀態 x（想知道的）= [px, py, vx, vy]ᵀ     位置 m、速度 m/s
量測 z（拿得到的）= [px, py]ᵀ              只有位置
```
- 速度**沒有感測器在量**，要靠濾波器推。這是把速度放進狀態的原因：只要它跟位置有物理關係（位置 = 位置 + 速度×dt），濾波器就推得出來。
- **單位一律 SI**（m、m/s、m/s²、s）寫死在註解裡 —— 單位混用是最常見、最難查的 bug。

### STEP 2　運動模型 F(dt)：沒有新資訊時，目標「應該」怎麼動？
等速模型（Constant Velocity, CV）：
```
          ┌ 1  0  dt  0 ┐         px ← px + vx·dt
   F  =   │ 0  1  0  dt │         py ← py + vy·dt
          │ 0  0  1   0 │         vx ← vx
          └ 0  0  0   1 ┘         vy ← vy
```
模型不必完美 —— 「模型錯多少」交給 STEP 4 的 Q。dt 寫成參數，因為真實感測器的間隔常常不固定。

### STEP 3　量測模型 H：感測器「看到」狀態的哪些部分？
```
   H = ┌ 1  0  0  0 ┐       z = H·x + 雜訊      → 只挑出 px、py
       └ 0  1  0  0 ┘
```

### STEP 4　過程雜訊 Q(dt, σ_a)：模型錯多少？—— 從物理推出來
CV 模型說「速度不變」，真實目標卻會加速、轉彎。把這些**沒建模的加速度**當成雜訊 a ~ N(0, σ_a²)，
假設它在每個 dt 內是常數（離散白噪加速度模型，DWNA）。一個 dt 內，加速度 a 會讓：
```
   位置多走 ½·a·dt²        速度多了 a·dt        → G = [½dt², dt]ᵀ（每一軸）

                 ┌ dt⁴/4    0     dt³/2    0   ┐
   Q = σ_a² ·    │   0    dt⁴/4    0     dt³/2 │ = G·σ_a²·Gᵀ
                 │ dt³/2    0      dt²     0   │
                 └   0    dt³/2    0      dt²  ┘
```
- **σ_a 的物理意義**：「目標在一個 dt 內，可能出現多猛的、模型沒料到的加速度」（m/s²）。
- 經驗法則：σ_a ≈ 目標最大加速度的 **0.5～1 倍**。人走路 ~0.5、一般車輛 1～3、無人機 2～5。
- 本例目標轉彎時向心加速度 ≈ 0.79 m/s²、直線加速 0.3 m/s² → 取 **σ_a = 0.8**。
- 非對角的 dt³/2：同一個加速度「同時」推動位置和速度，所以兩者的誤差是相關的。**只填對角線是常見錯誤。**

> 調一個有物理意義的 σ_a，遠比亂調 Q 的 16 個數字有意義。

### STEP 5　量測雜訊 R：感測器有多不準？—— 直接看規格書
```
   R = σ_z² · I     例：GPS 1σ = 3 m → R = diag(9, 9) m²
```
規格書常寫的不是 1σ（假設兩軸 σ 相同）：**CEP（50% 圓）≈ 1.18σ、95% 圓 ≈ 2.45σ、2DRMS ≈ 2.83σ**，要先換算回 1σ。
感測器若每筆回報精度（如 GPS 的 HDOP），可以每筆給不同的 R：`kf.update(z, R=...)`。

### STEP 6　初始化：第一筆量測進來，什麼都不知道時怎麼開始？
```
   x₀ = [zx, zy, 0, 0]ᵀ          P₀ = diag(σ_z², σ_z², v_max², v_max²)
```
- 位置：相信第一筆量測，不確定度 = 感測器雜訊。
- 速度：不知道就填 0，但給**超大**的不確定度 v_max²（本例 20² = 400）。**「我不知道」就用大 P 表示。**
- 效果：第一次更新 K[0,0] = 0.94、K[2,0] 也很大 → 兩三筆量測速度就被推出來（動畫 k = 1～3）。
- 另一種常見做法：兩點初始化（等第二筆，用差分當初始速度）。

### STEP 7　預測 predict(dt)
```
   x⁻ = F·x
   P⁻ = F·P·Fᵀ + Q
```
- F·P·Fᵀ：把舊的不確定度「搬」到新時刻 —— 速度的不確定，經過 dt 就變成位置的不確定。
- \+ Q：這段時間模型可能出錯的量。→ **P 一定變大**（沒有新資訊，只會更不確定）。
- **可變 dt**：每次都用「這筆與上筆的實際時間差」重算 F(dt)、Q(dt)。dt < 0（亂序）直接報錯。

### STEP 8　創新 innovation：量測跟預測差多少？應該差多少？
```
   y = z − H·x⁻          量到的 − 預測會量到的（驚訝程度）
   S = H·P⁻·Hᵀ + R       落差「應該」多大 = 預測的不確定 + 感測器雜訊
```
y 和 S 要一起看：落差 10 m 算大嗎？若 S 說「正常就會差 ±20 m」，那 10 m 很正常。

### STEP 9　閘門 gating：這筆量測可信嗎？
```
   NIS = yᵀ·S⁻¹·y        （馬氏距離的平方：落差是「幾個標準差」的平方）
```
- 模型正確時 NIS 服從**自由度 = 量測維度（2）的卡方分佈**。
- 門檻怎麼來：2 自由度卡方剛好有封閉解 **P(NIS > g) = e^(−g/2) → g = −2·ln(1 − p)**

  | 信心水準 p | 門檻 g | 意思 |
  |---|---|---|
  | 95% | 5.99 | 正常量測有 5% 會被誤殺 |
  | **99%** | **9.21** | 正常量測只有 1% 會被誤殺（本專案） |
  | 99.9% | 13.82 | 更寬鬆 |

- NIS > 9.21 → 判為離群值（多路徑跳點），**不更新**，狀態維持預測值。本例 3 個跳點的 NIS = 27.7、55.5、60.6，全部擋下。
- **副作用與保險絲**：如果是濾波器自己跟丟了（σ_a 太小、轉彎跟不上），好的量測也會被一直拒絕 → 永遠回不來。
  工程版加一條：**連續被拒 3 次 → 判定「錯的是濾波器」→ 用目前量測重新初始化**。

### STEP 10　增益 K：這次要聽量測幾成？
```
   K = P⁻·Hᵀ·S⁻¹         （4×2）
```
- 1D 直覺：K = P⁻ / (P⁻ + R)。本例穩態 **K[0,0] = 0.43**：每次往量測方向修正 43%。
- 第 3、4 列（速度那兩列）：**K[2,0] = 0.121** → x 方向每偏 1 m，x 速度修正 0.121 m/s。**速度就是這樣被推出來的。**
- **用 `np.linalg.solve`，不用 `inv(S)`**：
  1. 精度：solve 用 LU 分解直接解方程，少一次捨入；S 接近奇異時差很多。
  2. 速度：少一次矩陣乘法。
  3. 數值計算通則：「需要 A⁻¹b 時，解 Ax = b」。
  推導：K·S = P⁻Hᵀ → 轉置（S、P⁻ 對稱）→ S·Kᵀ = H·P⁻ → `K = solve(S, H @ P).T`。

### STEP 11　更新 update：把量測融合進來
```
   x = x⁻ + K·y
   P = (I − K·H)·P⁻·(I − K·H)ᵀ + K·R·Kᵀ        ← Joseph form
   P = (P + Pᵀ) / 2                             ← 強制對稱
```
**為什麼工程上不用教科書的 P = (I − K·H)·P⁻？**
- 那條式子只有在 K「剛好是最佳增益」時才成立。浮點誤差（或 K 被限幅、被手動改過）會讓它算出**不對稱、甚至負的變異數**，濾波器就慢慢發散。
- Joseph form 是「兩個半正定矩陣相加」，**結構上保證對稱半正定**，對 K 的小誤差也不敏感。
- 多幾次 4×4 乘法，換長時間運作不發散 —— 很划算。`kalman_2d.py` 的自我檢查會確認每一步的 P 都對稱正定。

### STEP 12　量測遺失（z = None）→ 只預測、不更新
- P 會一直變大（動畫裡隧道那段，橘色橢圓一路長大：1σ 從 3.3 m 長到 12.8 m）= **誠實地說「我越來越不確定」**。
- 量測回來時，因為 P⁻ 大 → K 大（動畫 k = 44 時 K[0,0] 跳到 0.9）→ 很快被拉回。
- ❌ 不要「沿用上一筆量測」：那是餵假資料，還會讓 P 錯誤地縮小。

### STEP 13　健康監控：現場沒有真值，怎麼知道 Q、R 設得對不對？
看 **NIS 的長期平均**（不需要真值！這是現場唯一拿得到的「考卷」）：
```
   E[NIS] = 量測維度 = 2                          ← 模型與 Q、R 都正確
   N 筆平均的 95% 區間 ≈ 2 ± 1.96·√(4/N)          ← 卡方(2) 的變異數 = 4
```
| 平均 NIS | 意思 | 處置 |
|---|---|---|
| 明顯 > 2 | 實際落差比濾波器以為的大 → **過度自信** | Q（σ_a）或 R（σ_z）設太小 → 調大 |
| ≈ 2 | 誠實 | 不用動 |
| 明顯 < 2 | 實際落差比以為的小 → **過度保守** | Q 或 R 設太大 → 調小 |

函式庫提供 `nis_health(kf.nis_history)` 直接給結論。本例預設參數：平均 NIS = 1.70，落在 [1.45, 2.55] 內 ✓。
（開閘門時，被拒的大 NIS 不進統計，平均會略低一點點，99% 門檻下約 1.9，可忽略。）

## 五、Q、R 怎麼調（工程經驗）

### 調參順序
1. **R 先定**：看規格書；更好的是做「靜態測試」—— 感測器放著不動錄 10 分鐘，算位置的標準差。
2. **σ_a 用物理估**：目標最大加速度的 0.5～1 倍。
3. **用 NIS 微調**：跑真實資料，平均 NIS 往 2 靠。
4. **看殘差有沒有規律**：轉彎時 NIS 一直偏大 → 模型不夠（考慮 IMM，見第十章）。

### 真正決定行為的只有一個比值
穩態下（固定 dt、一直有量測），K 只由**追蹤指數 λ = σ_a·dt² / σ_z** 決定（這就是經典的 α-β 濾波器）：

| λ | 穩態 K[0,0]（α） | 穩態 K[2,0]·dt（β） | 行為 |
|---|---|---|---|
| 0.01 | 0.13 | 0.009 | 非常平滑、非常遲鈍 |
| 0.1 | 0.36 | 0.080 | |
| **0.16（本例）** | **0.43** | **0.121** | |
| 0.5 | 0.63 | 0.305 | |

## 六、「工程版」跟教科書版差在哪

| 項目 | 教科書版 | 工程版（本專案） | 為什麼 |
|---|---|---|---|
| 時間間隔 | 固定 dt | **每筆用實際 dt** 重算 F、Q | 感測器不會準時；封包會延遲 |
| 離群值 | 照單全收 | **NIS 卡方閘門** | 一個 40 m 跳點會把估計拉歪十幾公尺 |
| 跟丟 | 沒提 | **連續被拒 N 次 → 重新初始化** | 閘門的副作用：跟丟就永遠回不來 |
| 協方差更新 | (I − KH)P⁻ | **Joseph form + 對稱化** | 長時間運作不發散 |

| 量測遺失 | 沒提 | **只 predict** | 隧道、封包遺失 |
| 初始化 | 隨便給 | **第一筆量測 + 大 P** | 收斂快、不會「自信地錯」 |
| 監控 | 沒提 | **NIS 統計** | 現場沒有真值，NIS 是唯一的考卷 |
| 中間量 | 算完就丟 | **回傳 dataclass**（y、S、NIS、K…） | 除錯、log、畫圖 |

## 七、容易卡住的疑問 與 常見的坑

### Q1：為什麼融合後會比兩邊都準？不是「平均」而已嗎？
因為是**依不確定度加權**的平均。兩個獨立的估計，變異數分別 a、b，最佳加權後的變異數是 ab/(a+b)，一定小於 min(a, b)。
1D 例子：預測 ±4 m、量測 ±5 m → 融合 ±3.1 m。

### Q2：速度明明沒量，怎麼估得出來？
靠 P 裡面「位置-速度」的相關項（非對角線）。預測時 F·P·Fᵀ 會讓位置與速度的誤差產生相關；
更新時 K 的速度列（K[2,0]、K[3,1]）就會根據位置落差修正速度。
白話：「預測位置一直比量測落後」→ 一定是速度估太小 → 把速度調大。

### Q3：K 為什麼會收斂成定值？
P 的遞迴（預測讓 P 變大、更新讓 P 變小）在固定 dt 下會達到平衡。到了平衡，K 就是常數 —— 這時卡爾曼濾波器就等於一個 α-β 濾波器。
函式庫的 `steady_state_gain()` 直接算出穩態 K。動畫下方 (b) 圖的灰色虛線就是它。

### Q4：2σ 橢圓為什麼只包含 86%，不是 95%？
1D 的 ±2σ 包含 95%；但 2D 的「馬氏距離 ≤ 2」橢圓只包含 1 − e^(−2) ≈ **86.5%**。
要 95% 的 2D 橢圓得用 √5.99 ≈ 2.45σ。（這也是規格書「95% 圓 ≈ 2.45σ」的由來。）

### 常見的坑
1. **單位混用**：km 和 m、度和弧度、ms 和 s。Q、R、dt、狀態必須同一套單位。
2. **dt 錯**：用固定 dt 但實際不固定；時間戳是 ms 卻當 s；資料亂序造成 dt < 0；重複時間戳 dt = 0。
3. **P 不對稱、負定**：用 Joseph form + 對稱化；開發時用 `np.linalg.eigvalsh(P) > 0` 檢查。
4. **R 給太小**：濾波器過度自信 → NIS 偏大 → 閘門一直拒收 → 跟丟（動畫把 σ_z 拉到 1 m 試試）。
5. **R 給太大**：閘門變得太寬，跳點全部放進來（σ_z = 20 時一個都沒擋）。
6. **初始化 P 太小**：濾波器要很久才「醒過來」；或第一筆剛好是跳點 → 考慮兩點初始化。
7. **Q 只填對角線**：忽略位置-速度的相關，速度估計會變差。用 G·σ_a²·Gᵀ。
8. **量測遺失時沿用上一筆**：餵假資料、P 錯誤縮小。正確做法是只 predict。
9. **座標系**：GPS 經緯度不能直接當公尺用 → 先轉成區域平面座標（ENU）。
10. **閘門 + Q 太小 = 死亡螺旋**：預測落後 → 好量測被拒 → 更落後 → … 一定要有保險絲（重新初始化）。

## 九、虛擬碼 + 複雜度

```python
def track(measurements, dts, sigma_a, sigma_z, gate=9.21, v_max=20.0):
    H = [[1, 0, 0, 0],
         [0, 1, 0, 0]]
    R = sigma_z**2 * I2
    x = P = None
    for z, dt in zip(measurements, dts):
        if x is None:                          # STEP 6：第一筆量測 → 初始化
            if z is None:
                continue
            x = [z[0], z[1], 0, 0]
            P = diag(sigma_z**2, sigma_z**2, v_max**2, v_max**2)
            continue

        F, Q = cv_model_2d(dt, sigma_a)        # STEP 2、4（每次用實際 dt）
        x = F @ x                              # STEP 7：預測
        P = F @ P @ F.T + Q

        if z is None:                          # STEP 12：遺失 → 只預測
            continue

        y = z - H @ x                          # STEP 8：創新
        S = H @ P @ H.T + R
        nis = y @ solve(S, y)                  # STEP 9：閘門
        if nis > gate:
            continue                           # 離群值：不更新（工程版另有「連續被拒」保險絲）

        K = solve(S, H @ P).T                  # STEP 10：增益（不求逆）
        x = x + K @ y                          # STEP 11：更新（Joseph form）
        I_KH = I4 - K @ H
        P = I_KH @ P @ I_KH.T + K @ R @ K.T
        P = (P + P.T) / 2
        nis_log.append(nis)                    # STEP 13：健康監控
    return x, P
```

**複雜度**：每個時刻只有幾次 4×4、4×2 的矩陣運算（固定大小）→ 每步 **O(1)**，整段 **O(n)**。
在微控制器上跑到 kHz 等級都沒問題，這也是卡爾曼濾波器幾十年來到處都在用的原因之一。

## 十、延伸：EKF / UKF、IMM、RTS smoother

```
   線性模型、線性量測            → 卡爾曼濾波器 KF               ← 本專案
   量測非線性（雷達：距離+方位角）→ EKF（用 Jacobian 線性化）
                                  → UKF（用 sigma points，不必算 Jacobian）
   目標一下等速、一下轉彎         → IMM（多個模型並行，依機率混合）
   事後處理、可以用「未來」的資料 → RTS smoother（往回再修一遍，更平滑）
   固定 dt、只要穩態              → α-β 濾波器（= 穩態 KF，見第五章）
```
- **EKF**：雷達量的是 (r, θ)，h(x) = (√(px² + py²), atan2(py, px)) 是非線性的 → 在 x⁻ 附近用 Jacobian 當 H。
- **UKF**：挑一組「sigma points」丟進非線性函式，再統計回平均與協方差；比 EKF 好寫也通常更準。
- **IMM**：同時跑 CV、CA（等加速）、CT（等速率轉彎）幾個濾波器，依「哪個模型最能解釋量測」動態加權 —— 本例轉彎時 NIS 偏高的問題就是 IMM 要解決的。
- **RTS smoother**：先正向跑完卡爾曼，再從最後一筆往回修正。即時系統用不到，但軌跡後處理（例如事後分析行車紀錄）很好用。
- **多目標**：多個目標時，還要先決定「哪個量測屬於哪個目標」（資料關聯：GNN、JPDA、MHT），閘門就是第一道篩選。

---

### 最後再濃縮成三句話
1. **設計思路**：先定問題（狀態、量測、單位）→ 定模型（F、H）→ 定雜訊（Q 從物理、R 從規格）→ 才寫演算法 → 最後加工程防呆（可變 dt、閘門、Joseph、遺失、保險絲、NIS 監控）。
2. **每一步在做什麼**：預測讓狀態往前走、不確定度變大；量測進來先算落差 y 和「應有的落差」S，用 NIS 判斷可不可信，再用 K = P⁻Hᵀ S⁻¹ 決定聽幾成，更新後不確定度變小。
3. **為什麼有效**：兩個都不準的資訊依「誰比較準」加權，結果比兩邊都準；而 P 裡位置與速度的相關性，讓量不到的速度也能從位置的落差中被推出來。
