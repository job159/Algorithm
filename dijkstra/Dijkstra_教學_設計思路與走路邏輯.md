# Dijkstra 最短路徑：設計思路 與 走路邏輯（白話詳解）

> **一句話總結**：Dijkstra 像「火從起點蔓延」——便宜的路燒得快、貴的路燒得慢；
> 我們**永遠先處理火最早燒到的那一格**，所以一旦燒到某格，它的「最短到達時間（距離）」
> 就確定了。把每一格「火是從哪格燒過來的」記下來，從終點往回追，就是最短路。

## 一、先搞懂：要解的是什麼問題

地圖上每一格**進入時要付出不同的「成本」**（平地 1、草地 3、泥沼 6、高山 9…）。
我們要找的不是「格數最少」的路，而是**「總成本最低」**的路。

```
        ┌─────────────────────────────┐
   S ───┤   一大片高成本沼澤 (9)       ├─── G
        │   直直穿過去 = 8 格但很貴     │
        └─────────────────────────────┘
        ↑ 往上繞便宜平地 = 14 格但很便宜（總成本只要 14）
```

- **BFS（廣度優先）**：每一步都當成 1，找的是「格數最少」→ 會直直穿過沼澤（8 格、成本 40）。
- **Dijkstra**：把每格成本算進去，找「總成本最低」→ 寧可繞遠路走便宜地（14 格、成本 14）。

> 👉 **這就是為什麼有了 BFS 還需要 Dijkstra**：當「每一步的代價不一樣」時，最短路就不再是格數最少的那條。

## 二、設計思路：Dijkstra 是怎麼「想」出來的

### 笨方法：把所有路都試一遍
從 S 到 G 的走法多到爆炸（指數級），一條一條算總成本再挑最小——電腦也會算到天荒地老。**不可行。**

### 關鍵靈感：貪婪——「永遠先處理目前最便宜的那一格」

Dijkstra 的核心只有一句話：

> **在「還沒確定」的格子裡，挑出目前已知距離最小的那一格，把它的距離「拍板定案」。**

為什麼可以這麼大膽地「拍板」？因為——

### 為什麼貪婪是對的（這段最重要）

假設現在「還沒確定」的格子裡，**X 的已知距離最小，是 d**。
有沒有可能之後出現一條「繞別條路到 X」的更短路？

**不可能。** 任何「繞別條路到 X」的走法，都必須先經過另一個「還沒確定」的格子 Y，
而 Y 的距離 ≥ d（因為 X 是最小的）。再從 Y 走到 X 又要再加上**非負的成本**，
所以繞路到 X 的距離 ≥ d + (正成本) > d。

```
   S ......(d).......► X     ← 直接到 X：距離 d（目前最小）
    \                  ▲
     \....(≥d)..► Y ───┘     ← 想繞路？先到 Y 就已經 ≥ d，再走過來只會更大
                  +正成本
```

→ 既然沒有任何走法能比 d 更短，**d 就是 X 的最短距離，當場確定，以後不用再改。**
這就是 Dijkstra 敢「拍板」的底氣，也是它比笨方法快無數倍的原因。

> ⚠️ 注意這個論證用到「**成本非負**」。一旦有負成本，「繞路只會更大」就不成立，Dijkstra 會出錯（見 [第五節](#五三個最容易卡住的疑問)）。

### 白話比喻：火災 / 水波

把起點想成火源，每格成本 = 火要燒過那格需要的「時間」。火同時往四面八方蔓延：
- 便宜的格子燒得快、貴的格子燒得慢。
- **火第一次燒到某格的時間，就是該格的最短距離。**
- Dijkstra 做的事 = **照「火燒到的先後順序」一格一格處理**（誰最早被燒到就先處理誰）。

「優先佇列（min-heap）」就是用來隨時找出「下一個會被燒到的格子」的工具。

## 三、走路邏輯：拆成 5 個動作

每「單步」其實就是重複做這幾件事。記住四個詞：**dist、優先佇列、鬆弛、來源**。

### 動作 0：準備（reset）
- `dist[起點] = 0`，其它所有格子 `dist = ∞`（還沒走到）。
- 把起點丟進**優先佇列**。
- `parent`（來源簿）清空。

### 動作 1：取出最小（pop）
從優先佇列拿出**目前 dist 最小**的格子，叫它 `u`。
> 這就是「火接下來會燒到的那一格」。

### 動作 2：拍板（settle）
把 `u` 標記為「已確定」。根據 [第二節](#為什麼貪婪是對的這段最重要) 的道理，
`dist[u]` 從這一刻起就是**最短距離，永遠不再變**。
> 如果 `u` 就是終點 G → 結束，答案就是 `dist[G]`。

### 動作 3：鬆弛（relax）★ 演算法的靈魂
看 `u` 的每個鄰居 `v`，問一句：

> 「**經由 u 走到 v**，會不會比 v 現在已知的路更近？」

計算 `新距離 = dist[u] + 進入 v 的成本`：
- **更短** → 更新 `dist[v] = 新距離`（找到更便宜的走法了！），並執行動作 4。
- **沒更短** → 不動（v 早就有一樣好或更好的路）。

```
   u(dist=5) ──成本3──► v
   新距離 = 5 + 3 = 8
   ├ 若 dist[v] 原本 = ∞ 或 12 → 8 更小 → 更新成 8！
   └ 若 dist[v] 原本 = 6        → 8 沒比較小 → 不更新
```

「鬆弛 relax」這名字的意思：把 v「過度估計的距離」慢慢**放鬆、修正得更小、更接近真實**。

### 動作 4：記來源（parent）
每次鬆弛成功（更新了 `dist[v]`），就順手記一筆：

> `parent[v] = u` —— 「目前到 v 最便宜的走法，最後一步是從 u 過來的。」

**這一筆是整個演算法的伏筆。** 搜尋時我們只顧著算距離，但每一格都默默記住了
「我是從哪一格來的」。這些 `parent` 連起來就是一棵**最短路徑樹**
（動畫裡的藍色箭頭）。

### 動作 5：回推（backtrack）
一直重複動作 1～4，直到拍板的格子是終點 G。這時：

> 從 **G** 出發 → 看 `parent[G]` 是誰 → 再看它的 parent → … → 一路退回 **S**。

把這串倒過來，就是最短路徑。**路徑不是另外算的，是沿著早就記好的來源箭頭撿回來的。**

```
   G ◄─ parent ─ C ◄─ parent ─ B ◄─ parent ─ A ◄─ parent ─ S
   倒過來：S → A → B → C → G  （這就是答案）
```

## 四、跟著手算走一遍（小例子）

5 個點、邊上的數字是成本（雙向）。求 S → G 最短路：

```
            2          1
        S ──────► A ──────► B
        │         │         │
       5│        7│        8│
        │         │  3      │
        ▼         ▼ ◄────── ▼
        （B─3─C，C─1─G）
   邊：S-A=2  S-B=5  A-B=1  A-C=7  B-C=3  B-G=8  C-G=1
```

逐步追蹤（`∞` = 還沒走到；粗體 = 這步更新的）：

| 步驟 | 取出(拍板) | 鬆弛動作 | dist 表 (S,A,B,C,G) | 優先佇列(剩下的) |
|---|---|---|---|---|
| 0 | — | 初始化 | 0, ∞, ∞, ∞, ∞ | S(0) |
| 1 | **S**(0) | A=0+2=2、B=0+5=5 | 0, **2**, **5**, ∞, ∞ | A(2), B(5) |
| 2 | **A**(2) | B=2+1=**3**(<5,更新)、C=2+7=9 | 0, 2, **3**, **9**, ∞ | B(3), C(9) |
| 3 | **B**(3) | C=3+3=**6**(<9,更新)、G=3+8=11 | 0, 2, 3, **6**, **11** | C(6), G(11) |
| 4 | **C**(6) | G=6+1=**7**(<11,更新) | 0, 2, 3, 6, **7** | G(7) |
| 5 | **G**(7) | 是終點 → 結束 | 0, 2, 3, 6, **7** | （完成） |

**重點觀察：**
- 第 2 步：到 B 原本走 S→B 是 5，但發現 S→A→B 只要 **3**，更便宜 → 更新，`parent[B]` 改成 A。
- 第 3 步：到 C 原本是 9（走 A），發現走 B 只要 **6** → 更新，`parent[C]` 改成 B。
- 雖然 S→B 直線只要一步，最後的最短路反而繞經 A。**這就是「最短 ≠ 最少步」的活例子。**

**回推**：`G ← C ← B ← A ← S`，倒過來 = **S → A → B → C → G，總成本 7**（2+1+3+1）。

## 五、三個最容易卡住的疑問

### Q1：為什麼一格「第一次被取出」就保證是最短？之後不會更短嗎？
因為取出時它是**所有未確定格子裡 dist 最小的**，而其它任何路徑都得先經過一個
「dist ≥ 它」的格子、再加上**非負成本**，只會更大不會更小。所以不可能再被刷新。
（完整論證見 [第二節](#為什麼貪婪是對的這段最重要)。）這也是為什麼「拍板」後我們就把它放進
`settled`，再也不碰。

### Q2：動畫/程式裡說的「過期項目」是什麼？
我們用 min-heap 當優先佇列。當鬆弛把某格距離改小，我們是**再塞一筆新的 (更小距離, 格子)** 進堆，
而**舊那筆沒刪掉**（堆不好刪中間）。於是堆裡同一格可能有好幾筆。
取出時若發現「這格已經拍板過了」，就知道這是舊的、**直接跳過**。
這叫「**惰性刪除（lazy deletion）**」——簡單、實務上很常用。

### Q3：為什麼成本不能是負的？
Dijkstra 的「拍板就不再改」完全建立在「**走更多步只會更貴**」。
若有負成本，可能繞一圈反而變便宜，已拍板的格子就可能被推翻——前提崩潰，答案就錯了。
> 有負邊要用 **Bellman-Ford**；負邊還成環無限變小則無解。

## 六、對照我們的動畫畫面

| 動畫上的東西 | 對應的概念 |
|---|---|
| 每格中央的**大數字** | `dist`：目前已知的最短距離（`∞` = 還沒走到） |
| 格子右上角**小徽章** | 進入這格的成本（地形權重） |
| 下方一排**方塊（min-heap）** | 優先佇列；最左橘色 = 下一個要取出的（dist 最小） |
| 橘色外框那格 | 這一步正在處理的 `u`（剛拍板） |
| 淺藍色格子 | 已確定（settled） |
| 黃色格子 | 在佇列中、還沒確定（frontier） |
| 藍色解說框 | 即時把這一步的鬆弛逐句講白話 |
| **藍色細箭頭** | `parent` 來源：「我是從哪格來的」，連起來是最短路徑樹 |
| **金線從 G 往 S 長** | 回推：沿來源箭頭把最短路撿回來 |
| 黃色**路徑容器** | 把回推撿回的整條路一格一格收集進盒子 |

**建議看法**：按「單步」，盯著三件事——
① 佇列每次是不是都取**最小**的？
② 被取出的格子去**鬆弛**鄰居，哪些 `dist` 變小了（藍色解說會講）？
③ 藍色箭頭怎麼長成一棵指回 S 的樹？
最後走到 G，看金線**從 G 倒著長回 S**——那一刻就懂「為什麼這樣走能找到這條路」了。

## 七、虛擬碼 + 複雜度

```python
def dijkstra(graph, S, G):
    dist = {S: 0}                 # 其它預設視為 ∞
    parent = {}
    settled = set()
    heap = [(0, S)]               # (距離, 格子)，min-heap

    while heap:
        d, u = pop_min(heap)      # 動作1：取出 dist 最小
        if u in settled:          # Q2：過期項目，跳過
            continue
        settled.add(u)            # 動作2：拍板（dist[u] 從此確定）
        if u == G:
            break                 # 碰到終點就結束

        for v in neighbors(u):    # 動作3：鬆弛每個鄰居
            nd = d + cost_to_enter(v)
            if nd < dist.get(v, INF):
                dist[v] = nd
                parent[v] = u     # 動作4：記來源
                push(heap, (nd, v))

    # 動作5：回推
    path, cur = [], G
    while cur in parent or cur == S:
        path.append(cur)
        if cur == S: break
        cur = parent[cur]
    path.reverse()
    return dist.get(G, INF), path
```

**複雜度**（V = 格子數，E = 邊數）：
- 每格最多被拍板一次、每條邊最多鬆弛一次，每次堆操作 `O(log V)`。
- 總共 **`O((V + E) · log V)`**。在格子地圖上 E ≈ 4V，所以約等於 `O(V log V)`，非常快。

## 八、和 BFS / A* 的關係

- **BFS** 其實就是「**所有成本都 = 1 的 Dijkstra**」：佇列先進先出剛好等於按距離排序。
  （你可以在動畫裡把地形全清成平地，Dijkstra 的行為就退化成 BFS 的直線路。）
- **A\***（A-star）= Dijkstra **再加一個「離終點還有多遠」的估計值**當方向感，
  優先往終點方向探，找一樣的最短路但通常更快。把 A* 的估計值設成 0，就變回 Dijkstra。

```
   均勻成本、要最短  → BFS
   不同成本、要最短  → Dijkstra          ← 本專案
   不同成本、要更快  → A*（Dijkstra + 方向感）
   有負成本          → Bellman-Ford
```

---

### 最後再濃縮成三句話
1. **設計思路**：永遠先「拍板」目前最便宜的格子；因為成本非負，它不可能再更短了。
2. **走路邏輯**：取最小 → 拍板 → 鬆弛鄰居（更便宜就更新並記來源）→ 重複 → 回推。
3. **為什麼能找到路**：每格都記了「從哪來」，從 G 沿來源一路退回 S，就是最短路。
