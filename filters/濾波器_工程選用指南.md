# 工程常用濾波器：選用指南（設計思路 與 一步一步的計算）

> **一句話總結**：濾波器不是越強越好，而是「**先認出雜訊長什麼樣子，再挑對付它的那一種**」——
> 細碎抖動（白噪）用**平均**、偶發大跳（尖峰）用**排序**、慢慢歪掉（漂移）用**融合**、
> 要跟得緊就加**模型（速度）**；而所有因果濾波器都逃不掉同一個取捨：**越平滑，就越延遲**。

這份文件搭配同資料夾的兩支程式一起看最有感：
- `filters.py`：9 個濾波器的函式庫（只依賴 numpy；每個都是 `update(x) -> y` 的串流式類別）。
- `filters_pyqt6_step.py`：逐點動畫，每吃一個取樣就畫出濾波器的內部狀態，並用真實數字解說。

（卡爾曼濾波在隔壁的 `kalman_filter/` 資料夾；本文第六節說明兩者的關係。）

## 一、先搞懂：雜訊有哪幾種、該用哪種濾波

挑濾波器之前，先把原始資料畫出來看一眼。工程上最常見的四種「髒」：

| 雜訊種類 | 長相 | 典型來源 | 對付它的思路 |
|---|---|---|---|
| **高斯白噪** | 每一點都在真值附近細碎亂抖，正負機會均等 | 熱雜訊、ADC 量化以外的電路雜訊、振動 | **平均**：正負抵消 |
| **尖峰脈衝** | 平常很乾淨，偶爾一兩點跳到離譜的值 | 接觸不良、EMI 干擾、測距打到雜物、通訊錯碼 | **排序**：極端值被擠到兩端 |
| **漂移** | 不抖，但整條線慢慢歪掉 | 陀螺儀偏差積分、溫度漂移、零點偏移 | **融合 / 高通**：用另一個長期準的感測器拉回來 |
| **量化** | 階梯狀，只能取某些固定值 | ADC 位數太少、編碼器解析度 | 平均可以「插值」出更細的值；要小心 MAD = 0 |

### 決策樹

```
看一眼原始資料：雜訊長什麼樣子？
│
├─ 偶爾一兩點離譜（尖峰脈衝）
│    ├─ 其他點想保留原始細節 ─────────────► Hampel
│    └─ 全部換成中位數也行、還要保邊緣 ───► Median
│       （剔完尖峰若還有白噪，再串一個平均類）
│
├─ 細碎抖動（高斯白噪）
│    ├─ 需要明確規格（fc、衰減斜率）───────► Biquad（可串成高階 SOS）
│    ├─ 記憶體 / 算力極少 ─────────────────► EMA
│    ├─ 要線性相位、或要消固定週期干擾 ───► MA
│    └─ 平滑之後延遲太大、跟不上？
│         ├─ 近似等速移動（追蹤、編碼器）─► Alpha-Beta（多估一個速度）
│         └─ 時快時慢（手、游標、頭部）───► One Euro（速度自適應）
│
├─ 整條線慢慢歪掉（漂移）
│    ├─ 有第二個「長期準、短期吵」的感測器 ► 互補濾波
│    └─ 沒有，只需要「變化量」────────────► Biquad 高通
│
└─ 不是雜訊，而是「輸出不准變太快」────────► RateLimiter
```

> 👉 **最常見的組合拳**：`Hampel（剔尖峰）→ EMA 或 Biquad（壓白噪）`。順序不能反：
> 先平均的話，尖峰已經被「攤開」成一個小方塊，排序類就認不出來了。

## 二、根本取捨：延遲 vs 平滑

**因果濾波器**（只能用現在與過去的資料，即時系統一定是這種）有一個逃不掉的定律：

> 想把雜訊壓得越平，就必須參考越多「過去」的資料 → 輸出就越像「過去的訊號」→ 越延遲。

```
   真值   ─────────╱‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾      （步階：在 k=0 跳上去）
   原始   ─·─·─·─·─╱·‾·‾·‾·‾·‾·‾·‾·‾      不延遲，但很抖
   輕濾波 ─────────╱‾‾‾‾‾‾‾‾‾‾‾‾‾‾      慢 1～2 點，還有一點抖
   重濾波 ──────────────╱‾‾‾‾‾‾‾‾‾      很平滑，但慢了好幾點
                    ↑    ↑
                  真跳   重濾波才跟上（延遲）
```

以 N 點移動平均為例，可以把取捨寫成兩條公式：

| | 公式 | N=4 | N=16 |
|---|---|---|---|
| 剩下的白噪 | σ_out = σ / √N | 0.50 σ | 0.25 σ |
| 延遲 | (N−1)/2 點 | 1.5 點 | 7.5 點 |

雜訊只降一半（√4 → √16），延遲卻變成 5 倍。**平滑度的報酬是遞減的，延遲的代價是線性的。**

怎麼「作弊」少付一點延遲？本專案示範了三招：
1. **換更陡的濾波器**（Biquad）：同樣的雜訊抑制，延遲比 MA 小。
2. **加模型**（Alpha-Beta）：知道訊號「正在以某速度移動」，就能預測、抵銷斜坡延遲。
3. **自適應**（One Euro）：靜止時重濾波、移動時輕濾波——把延遲花在看不出來的地方。

> ⚠️ 只有「離線處理」才能真正零延遲：先正向濾一次、再反向濾一次（`scipy.signal.filtfilt`），
> 兩次相位抵消。但這需要整段資料（偷看未來），即時控制用不了。

## 三、九個濾波器逐一拆解

為了好比較，前四個濾波器都用**同一串手算資料**（真值大約是 3，第 4 點的 9 是尖峰）：

```
   k :  1   2   3   4   5   6   7
   x :  2   4   3   9   4   3   3
                    ↑ 尖峰
```

### 3-1 移動平均 MA

**直覺**：最近 N 點平均，白噪一正一負互相抵消。

**公式**：`y[k] = (x[k] + x[k−1] + … + x[k−N+1]) / N`

**設計（STEP）**
1. 環形緩衝存最近 N 點，寫入位置 `idx` 繞圈走。
2. 維護累加和 `S`：新點進來 `S += x_new`，最舊點被擠出 `S −= x_old` → 每步 O(1)。
3. 暖機（還沒滿 N 點）：除以「目前點數」，不是除以 N。
4. 浮點誤差：每 1000 步用 `math.fsum` 重算一次 S。（自我測試：一個 1e12 的尖峰經過後，不重算的誤差是 4.4e-05，重算後是 0。）

**手算（N=3）**

| k | x | 擠出 | S = S_prev + x − x_old | y = S ÷ 點數 |
|---|---|---|---|---|
| 1 | 2 | — | 0 + 2 = 2 | 2 ÷ 1 = **2.000**（暖機） |
| 2 | 4 | — | 2 + 4 = 6 | 6 ÷ 2 = **3.000**（暖機） |
| 3 | 3 | — | 6 + 3 = 9 | 9 ÷ 3 = **3.000** |
| 4 | 9 | 2 | 9 + 9 − 2 = 16 | **5.333** ← 尖峰進來 |
| 5 | 4 | 4 | 16 + 4 − 4 = 16 | **5.333** |
| 6 | 3 | 3 | 16 + 3 − 3 = 16 | **5.333** |
| 7 | 3 | 9 | 16 + 3 − 9 = 10 | **3.333** ← 尖峰離開 |

**觀察**：尖峰沒有被去掉，而是被「攤開」成高度 6/3=2、寬 3 點的小方塊。MA 不適合尖峰。

**參數**：N ≈ 2·(可接受延遲 D / dt) + 1。想消掉 60 Hz 干擾：讓 N·dt = 1/60 s 的整數倍。

**代價**：延遲 (N−1)/2 點、線性相位（波形不變形）；記憶體 N 個數。

### 3-2 EMA／一階低通

**直覺**：輸出每一步往新量測「走 α 的比例」。就是 RC 低通電路的數位版。

**公式**：`y[k] = α·x[k] + (1−α)·y[k−1]`，等價寫法 `y += α·(x − y)`

**設計（STEP）**
1. 想省記憶體 → 只存上一個輸出。
2. 新輸出 = 舊輸出往新量測走一小段（α）。
3. 展開後過去第 m 點權重 α(1−α)^m，呈指數衰減（IIR）。
4. RC 電路 `dV/dt = (Vin − V)/RC` 離散化 → **α = dt / (RC + dt)，RC = 1/(2π·fc)**。
5. 暖機：第一筆令 y = x。

**手算（α = 0.5）**

| k | x | y = 0.5·x + 0.5·y_prev |
|---|---|---|
| 1 | 2 | **2.0**（暖機：y = x） |
| 2 | 4 | 0.5×4 + 0.5×2 = **3.0** |
| 3 | 3 | 0.5×3 + 0.5×3 = **3.0** |
| 4 | 9 | 0.5×9 + 0.5×3 = **6.0** ← 尖峰 |
| 5 | 4 | 0.5×4 + 0.5×6 = **5.0** |
| 6 | 3 | 0.5×3 + 0.5×5 = **4.0** |
| 7 | 3 | 0.5×3 + 0.5×4 = **3.5** ← 指數尾巴還在 |

**換算例**：fc = 1 Hz、fs = 100 Hz → RC = 0.159 s、α = 0.01/(0.159+0.01) = **0.0591**；
同樣 1 Hz 但 fs = 20 Hz（動畫用的）→ α = **0.239**。**同一個 fc，取樣率不同，α 就不同**——直接寫死 α 的程式換了取樣率就會錯。

**參數**：α 等效於約 (2/α − 1) 點的 MA；時間常數 τ ≈ dt·(1−α)/α。

**代價**：低頻延遲約 (1−α)/α 點；1 乘 1 加、記憶體 1 個數；衰減只有 −20 dB/decade。

### 3-3 中位數濾波 Median

**直覺**：排序後取中間。尖峰是極端值，永遠被擠到兩端，碰不到中位數。

**設計（STEP）**
1. 同時維護「時間順序窗口」（決定誰該被擠出）與「已排序串列」（取中位數）。
2. 新值：二分搜尋找位置插入；最舊值：二分搜尋找到後刪除。
3. 取中間那一格（N 為奇數）；暖機或偶數個時取中間兩個的平均。

**手算（N=3）**

| k | 窗口（舊→新） | 排序後 | y |
|---|---|---|---|
| 3 | [2, 4, 3] | [2, **3**, 4] | **3** |
| 4 | [4, 3, 9] | [3, **4**, 9] | **4** ← 9 被擠到最右端 |
| 5 | [3, 9, 4] | [3, **4**, 9] | **4** |
| 6 | [9, 4, 3] | [3, **4**, 9] | **4** |
| 7 | [4, 3, 3] | [3, **3**, 4] | **3** |

**觀察**：尖峰 9 完全沒出現在輸出裡（MA 是 5.333、EMA 是 6.0）。但注意 k=4～6 的輸出是 4 不是 3：
中位數「每一點都換成中位數」，正常點的值也被改了。

**參數**：能去掉的最長連續尖峰 = (N−1)/2 點 → N ≥ 2·尖峰長度 + 1。常用 3、5、7。

**代價**：邊緣延遲約 (N−1)/2 點；每步 O(N)；對白噪的效率比 MA 差。

### 3-4 Hampel 離群值濾波

**直覺**：先判斷「這點是不是離群」，是才換成中位數，不是就原值照用。

**公式**
```
   med = median(窗口)
   MAD = median(|窗口 − med|)          ← 穩健的「離散程度」，不會被尖峰撐大
   σ   ≈ 1.4826 × MAD                  ← 常態分布下 MAD 換算成標準差
   |x − med| > k·σ ？ 是 → y = med（離群）   否 → y = x（原值）
```

**設計（STEP）**
1. 判斷要有一把尺。標準差會被尖峰撐大（自己騙自己）→ 改用 MAD。
2. 1.4826 = 1/Φ⁻¹(0.75)：讓 MAD 在常態分布下等於 σ。
3. k = 3 → 正常點被誤判的機率約 0.27%。
4. 因果版（窗口含目前這點）零延遲；置中窗口較準但要等 (N−1)/2 點。
5. MAD 可能為 0 → 給一個下限 `min_sigma`（例如 1 個 LSB）。

**手算（N=5、k=3）**

| k | 窗口 | med | MAD | 門檻 k·σ | \|x−med\| | 判定 | y |
|---|---|---|---|---|---|---|---|
| 3 | [2,4,3] | 3 | 1 | 3×1.483 = 4.45 | 0 | 正常 | **3** |
| 4 | [2,4,3,9] | 3.5 | 1 | 4.45 | 5.5 | **離群** | **3.5** |
| 5 | [2,4,3,9,4] | 4 | 1 | 4.45 | 0 | 正常 | **4** |
| 6 | [4,3,9,4,3] | 4 | 1 | 4.45 | 1 | 正常 | **3**（原值！） |
| 7 | [3,9,4,3,3] | 3 | **0** | **0** | 0 | 正常 | **3** |

**觀察**：
- k=6 跟 Median 的差別：Median 輸出 4，Hampel 保留原值 3——**好點一個都不碰**。
- k=7 的 MAD = 0、門檻 = 0：此時只要 x 是 3.01 就會被判離群。這就是要設 `min_sigma` 的原因。

**參數**：N 讓「窗口內尖峰數 < N/2」，常用 5～11；k 用 3（2 偏嚴、4～5 寬鬆）。

**代價**：零延遲，但不平滑白噪；真實步階的前幾點會被誤判（自我測試中 N=11 的步階延遲 3 點，之後 MAD 被撐大就放行）。

### 3-5 Alpha-Beta 追蹤

**直覺**：多估一個「速度」。先用速度預測下一點，再拿「量測 − 預測」（殘差）修正位置與速度。

**公式**
```
   ① 預測   x_pred = x + v·dt
   ② 殘差   r = z − x_pred
   ③ 修正   x = x_pred + α·r
   ④ 修正   v = v + (β/dt)·r
```

**設計（STEP）**
1. EMA 沒有速度概念 → 等速移動時永遠落後「斜率 × τ」。
2. 加一個速度狀態 → 可以預測。
3. 殘差告訴你預測錯多少；α、β 決定位置/速度各修多少。
4. 卡爾曼跑久了增益收斂成常數 K = [α, β/dt] → 這就是 Alpha-Beta（第六節）。

**手算（α=0.5、β=0.2、dt=1，量測是一條斜率約 1 的斜坡）**

| k | z | x_pred = x + v | r = z − x_pred | x = x_pred + 0.5r | v = v + 0.2r |
|---|---|---|---|---|---|
| 1 | 0 | — | — | **0**（暖機） | **0** |
| 2 | 1.2 | 0 + 0 = 0 | 1.2 | **0.600** | **0.240** |
| 3 | 1.9 | 0.6 + 0.24 = 0.84 | 1.06 | **1.370** | **0.452** |
| 4 | 3.1 | 1.37 + 0.452 = 1.822 | 1.278 | **2.461** | **0.708** |
| 5 | 4.0 | 2.461 + 0.708 = 3.169 | 0.831 | **3.584** | **0.874** |

**觀察**：速度 v 一步步長到接近真實斜率 1；收斂後預測就很準，殘差變小，**斜坡上沒有穩態延遲**。
（自我測試：斜坡上 Alpha-Beta 平均誤差 0.0063，EMA 是 0.0257。）

**參數**
- 有雜訊統計：追蹤指數 `λ = σ_a·dt²/σ_v` → `r = (4 + λ − √(λ²+8λ))/4`、`α = 1 − r²`、`β = 2(1−r)²`。
  例：λ = 0.1 → α = 0.36、β = 0.08；λ = 1 → α = 0.75、β = 0.5。
- 經驗值：先選 α（0.1～0.5），β = α²/(2−α)（Benedict–Bordner）。α = 0.3 → β = 0.053。
- 穩定條件：0 < α < 2、0 < β < 4 − 2α。

**代價**：等速時零穩態延遲；步階會過衝；尖峰會把速度帶歪 → 先過 Hampel。

### 3-6 互補濾波（IMU 姿態角）

**直覺**：陀螺儀「短期準但會漂」、加速度計「長期準但很吵」，兩個截長補短。

**公式**：`θ[k] = α·(θ[k−1] + ω[k]·dt) + (1−α)·a[k]`，`α = τ/(τ + dt)`

```
   陀螺儀 ω ──► 積分 ──► 高通（只信它的「變化」）──┐
                                                     (+) ──► θ
   加速度計 a ─────────► 低通（只信它的「長期值」）─┘
                         高通 + 低通 = 1 → 真實角度不失真（「互補」）
```

**設計（STEP）**
1. 陀螺儀積分：快、平滑，但 bias 一積分就變漂移。
2. 加速度計（重力方向）：長期平均準，但振動讓它很吵。
3. 陀螺儀走高通、加速度計走低通，兩個轉移函數相加剛好 = 1。
4. 寫成一行：先用陀螺儀往前推一步，再往加速度計「拉一點點」(1−α)。
5. τ 是分界：比 τ 快的變化信陀螺儀，比 τ 慢的信加速度計。

**手算（α = 0.98、dt = 0.01 s，上一刻 θ = 5.00°、陀螺 ω = 10°/s、加速度計 a = 5.30°）**

```
   陀螺預測   θ_pred = 5.00 + 10 × 0.01 = 5.10°
   陀螺項     0.98 × 5.10 = 4.998°
   加速度計項 0.02 × 5.30 = 0.106°
   θ = 4.998 + 0.106 = 5.104°
```

**參數**：τ ≈ 0.5～2 s。τ 太小 → 振動雜訊漏進來；τ 太大 → 漂移拉不回來，**穩態誤差 ≈ 陀螺偏差 × τ**
（偏差 2°/s、τ = 1 s → 約 2°）。

**代價**：幾乎零延遲；3 乘 2 加。自我測試：加速度計 6.15°、純陀螺積分 14.38°（最後漂了 25.6°），
互補濾波 **2.86°**——比任一感測器單獨都好。

### 3-7 Biquad 二階 IIR（Butterworth）

**直覺**：用兩格記憶 z1、z2 做出 −40 dB/decade 的陡峭低通（EMA 只有 −20）。

**公式**（Direct Form II Transposed）
```
   y  = b0·x + z1
   z1 = b1·x − a1·y + z2
   z2 = b2·x − a2·y
```
係數（RBJ Audio EQ Cookbook，低通）：
```
   w0 = 2π·fc/fs,   α = sin(w0)/(2Q)
   b0 = (1 − cos w0)/2,  b1 = 1 − cos w0,  b2 = (1 − cos w0)/2
   a0 = 1 + α,           a1 = −2 cos w0,   a2 = 1 − α        （全部再除以 a0）
```

```
   x ●────────┬──────────────┬──────────────┐
              │×b0           │×b1           │×b2
              ▼              ▼              ▼
             (+)◄──[ z1 ]◄──(+)◄──[ z2 ]◄──(+)
              │              ▲              ▲
              │              │×(−a1)        │×(−a2)
   y ◄────────┴──────────────┴──────────────┘
```

**設計（STEP）**
1. 一階太鈍 → 二階；Q 控制截止附近的形狀。
2. 類比原型 + 雙線性轉換 + 頻率預扭曲 = RBJ 公式；Q = 1/√2 就是 2 階 Butterworth。
3. DF2T 只要兩個狀態，浮點數值特性最好。
4. 要 4、6 階：串接多個 Biquad（SOS），每節用不同 Q（4 階 Butterworth：Q = 0.5412、1.3066）。
5. 暖機：預設 z = 0（與 scipy lfilter 相同）；`steady_init=True` 直接從穩態起跑。

**手算（fc = 1 Hz、fs = 20 Hz、Q = 0.707，輸入一直是 1，z 從 0 開始）**

係數：b0 = b2 = 0.0201、b1 = 0.0402、a1 = −1.5610、a2 = 0.6414（直流增益 = Σb/(1+a1+a2) = 1）

| k | 舊 z1 | 舊 z2 | y = b0·1 + z1 | 新 z1 | 新 z2 |
|---|---|---|---|---|---|
| 1 | 0 | 0 | **0.0201** | 0.0715 | 0.0072 |
| 2 | 0.0715 | 0.0072 | **0.0916** | 0.1904 | −0.0387 |
| 3 | 0.1904 | −0.0387 | **0.2104** | 0.3300 | −0.1149 |
| 4 | 0.3300 | −0.1149 | **0.3501** | 0.4718 | −0.2044 |
| 5 | 0.4718 | −0.2044 | **0.4919** | 0.6035 | −0.2954 |
| 6 | 0.6035 | −0.2954 | **0.6236** | 0.7183 | −0.3799 |

**觀察**：輸出是 S 形慢慢爬到 1（這就是「z = 0 開始」的暖機暫態）；z1、z2 一步步累積了「過去輸入與輸出的加權和」。

**參數**：fc 與 fs **都用 Hz**，fc < fs/2；Q = 0.707 最平坦、0.5 不過衝、> 0.707 會過衝振鈴（動畫拉 Q = 2.5 就看得到）。

**代價**：低頻延遲 ≈ 1/(Q·2π·fc) 秒（Butterworth 約 √2/(2π·fc)）；非線性相位；5 乘 4 加。
自我測試：與 `scipy.signal.lfilter` / `sosfilt` 逐點比對，最大誤差 1.4e-14。

### 3-8 One Euro Filter

**直覺**：會看速度調截止頻率的 EMA——靜止時很平滑、移動時延遲很小。

**公式**
```
   ① dx     = (x − y_prev)/dt,   dx_hat = EMA_{d_cutoff}(dx)      ← 速度也要先濾
   ② fc     = min_cutoff + β·|dx_hat|                              ← 動越快，fc 越高
   ③ α      = dt/(RC + dt), RC = 1/(2π·fc);   y = α·x + (1−α)·y_prev
```

**設計（STEP）**
1. EMA 兩難：fc 低靜止不抖但移動拖；fc 高跟得緊但靜止抖。
2. 人眼靜止時在意抖、移動時在意拖 → 讓 fc 跟著速度變。
3. 估速度並低通（速度比位置更吵）。
4. 自適應 fc → 算 α → 普通 EMA。

**手算（dt = 0.01 s、min_cutoff = 1 Hz、β = 0.5、d_cutoff = 1 Hz；y_prev = 0、新量測 x = 0.2）**
```
   dx     = (0.2 − 0)/0.01 = 20 /s
   dx_hat = 0.0591 × 20 + 0.9409 × 0 = 1.182        （d_cutoff = 1 Hz 的 α = 0.0591）
   fc     = 1 + 0.5 × 1.182 = 1.591 Hz
   α      = 0.0909
   y      = 0.0909 × 0.2 + 0.9091 × 0 = 0.0182
```

**參數（官方調法）**：β = 0 先把 min_cutoff 調到靜止不抖 → 再加大 β 直到移動不拖。
**β 的單位是 1/(訊號單位/秒)**：訊號用度、公尺、像素，β 差好幾個數量級（動畫在 IMU 訊號上自動把 β 縮小 30 倍）。

**代價**：自我測試（min_cutoff = 0.5 Hz）：β = 0 時步階延遲 22 點、靜止抖動 0.0073；
β = 0.1 → 延遲 **4 點**、抖動 0.0099；β = 0.5 → 延遲 2 點但抖動 0.0187（β 太大，雜訊本身就把 fc 撐高）。

### 3-9 斜率限制 RateLimiter

**直覺**：每一步最多只准變 max_rate·dt。小變化照走，大跳變被拉成斜坡。

**公式**：`y = y_prev + clip(x − y_prev, −max_fall·dt, +max_rate·dt)`

**設計（STEP）**
1. 目的不是去雜訊，而是「不准變太快」（保護馬達、閥門、使用者的眼睛）。
2. 想走 Δ = x − y_prev。
3. 允許 ±max_rate·dt（上升、下降可不同）。
4. 夾住。

**手算（每步最多 ±1.5）**

| k | x | 想走 Δ | 允許 | y |
|---|---|---|---|---|
| 1 | 2 | — | — | **2.0**（暖機） |
| 2 | 4 | +2.0 | ±1.5 | **3.5**（被夾） |
| 3 | 3 | −0.5 | ±1.5 | **3.0** |
| 4 | 9 | +6.0 | ±1.5 | **4.5**（尖峰只漏 1.5） |
| 5 | 4 | −0.5 | ±1.5 | **4.0** |
| 6 | 3 | −1.0 | ±1.5 | **3.0** |

**代價**：小訊號零延遲、零失真——所以**白噪會原封不動通過**；大步階要 |Δ|/max_rate 秒才走到。

|---|---|---|---|---|---|---|

## 五、常見坑

### 坑 1：fs 與 fc 的單位
- `butterworth_lowpass(fc, fs)` 兩個都是 **Hz**。最常見的錯：把 `fs` 填成取樣間隔 `dt`（0.01），
  或把 `fc` 填成 rad/s（2π·fc）。`filters.py` 會檢查 `fc < fs/2`，填錯通常會直接報錯。
- EMA 的 α 跟取樣率綁在一起：**改了取樣率，α 要重算**（1 Hz 在 100 Hz 是 0.059、在 20 Hz 是 0.239）。

### 坑 2：初始化 / 暖機
- EMA 從 y = 0 開始 → 開機那一段會從 0 慢慢爬上來，看起來像一個假的步階。解法：第一筆直接令 y = x。
- MA 暖機期除以 N（而不是目前點數）→ 一樣的假爬升。
- Biquad 的 z = 0 → 開頭有暫態；`steady_init=True` 直接從穩態起跑（動畫就是這樣設的）。
- Hampel 少於 3 點時 MAD 沒意義 → 一律當正常點。

### 坑 3：整數溢位（MCU 定點數）
- 12 位元 ADC（最大 4095）做 N = 32 點 MA：累加和最大 131,040，**超過 int16（32,767）**→ 要用 int32。
- 定點數 EMA 常寫成 `y += (x − y) >> k`（α = 1/2^k）：右移會把小差值截成 0，
  y 永遠到不了 x（「死區」）→ 把 y 放大 2^k 倍保存（多保留小數位）再輸出。
- Biquad 在定點數下，係數量化可能讓極點跑到單位圓外 → 用 SOS、或改用 DF1 方便飽和處理。

### 坑 4：相位延遲對控制迴路的影響
- 量測端的濾波器延遲 τ，在迴路穿越頻率 ωc 會吃掉 **ωc·τ 弧度**的相位裕度。
  例：ωc = 2π·5 Hz、τ = 20 ms → 吃掉 0.63 rad ≈ 36°，原本 45° 的相位裕度只剩 9°，系統開始振盪。
- 所以控制迴路裡的濾波器要「剛好夠用」：fc 至少放在穿越頻率的 5～10 倍以上，或改用延遲小的 Alpha-Beta / 互補濾波。

### 坑 5：先濾波，再微分
- 微分會把雜訊放大（頻率越高放大越多）：位置雜訊 σ = 1 mm、dt = 1 ms → 差分速度雜訊 ≈ √2 × 1/0.001 = 1.4 m/s！
- 正確做法：**先濾波再差分**，或直接用會順便估速度的 Alpha-Beta、One Euro 的 dx_hat。

### 坑 6：數位濾波救不了混疊（aliasing）
- 取樣前就已經高於 fs/2 的雜訊，取樣後會「摺疊」成低頻假訊號，數位濾波分不出真假。
  一定要在 ADC 前面放類比抗混疊濾波（RC 就好），數位濾波是第二道防線。

### 坑 7：dt 不固定
- 中斷抖動、通訊延遲讓 dt 忽大忽小 → EMA / 互補 / One Euro 的 α 應該用「實際量到的 dt」每步重算。

## 六、跟 kalman_filter 資料夾的關係

卡爾曼濾波每一步都在算「該多相信預測、多相信量測」的增益 K，而且 K 會隨不確定度 P 變化。
但只要系統模型與雜訊統計固定，P 跑一陣子就會收斂，**K 變成常數**——這時候卡爾曼退化成固定增益濾波器：

| 卡爾曼的模型 | 穩態時就等於 | 增益 |
|---|---|---|
| 位置不動 + 隨機漫步（1 個狀態） | **EMA** | α = 穩態 K |
| 等速模型（位置 + 速度，2 個狀態） | **Alpha-Beta** | K = [α, β/dt] |
| 等加速模型（3 個狀態） | Alpha-Beta-Gamma | K ∝ [α, β/dt, γ/dt²]（γ 前面的常數各書寫法不同） |

`filters.py` 的自我測試直接驗證了第二列：用 Riccati 方程式迭代出等速模型的穩態卡爾曼增益，
跟 `alpha_beta_from_tracking_index(λ)` 算出的 α、β 比對，誤差 < 1e-6。

```
   卡爾曼： 預測 → 算 P → 算 K（每步都變）→ 修正 → 更新 P
                              │  P 收斂後 K 變常數
                              ▼
   Alpha-Beta： 預測 → 修正（K 寫死成 α、β）    ← 省掉所有矩陣運算
```

> 👉 怎麼選：雜訊統計會變、要處理多感測器、需要知道「估得多準」（P）→ 卡爾曼；
> 系統穩定、MCU 很小、只要一個好用的追蹤器 → Alpha-Beta。

| 動畫上的東西 | 對應的概念 |
|---|---|
| **綠色虛線** | 真值（產生訊號時就知道，實際工程上看不到） |
| **灰點 + 灰細線** | 原始量測（濾波器的輸入）；IMU 訊號時是加速度計算出的角度 |
| **藍色粗線** | 濾波輸出，只畫到播放頭為止 |
| **琥珀色直線 + 「k = …」** | 播放頭：目前吃到第幾個取樣；右邊淡灰區是還沒發生的未來 |
| **橘色虛線**（IMU） | 純陀螺積分：不吵但越飄越遠——互補濾波要解決的問題 |
| **紅圈**（Hampel） | 被判為離群、換成中位數的點 |
| 「內部狀態」的**一排方塊** | MA / Median / Hampel 的窗口；琥珀 = 新進的值、虛線框 = 暖機期還空著 |
| 「排序後」那排的**綠框** | 中位數；尖峰被擠到兩端 |
| **綠色區間**（Hampel） | 正常範圍 med ± k·σ；新點落在外面就是離群 |
| **比例條**（EMA / 互補） | α 與 1−α 各佔多少 |
| **數線上的箭頭**（α-β） | ① 預測 v·dt → ② 殘差 r → ③ 修正 α·r |
| **z1、z2 琥珀方塊**（Biquad） | 兩個延遲暫存器的「舊值 → 新值」 |
| **三條量表**（One Euro） | 速度 → 自適應截止頻率 → 新量測權重 α |
| **想走 vs 允許**（斜率限制） | Δ 與 ±max_rate·dt 的長度比較 |
| 下方**解說框** | 「為何是這個輸出」：把這一步的公式代入真實數字 |
| **指標列** | RMSE（濾波 vs 真值、原始 vs 真值）與估計延遲（輸出往回挪幾點最貼近真值） |

**建議看法**（每個都只要一分鐘）：
1. **正弦 + 雜訊 × EMA**：停在任一點，把 fc 從 5 Hz 拖到 0.2 Hz——藍線越來越平、也越來越落後綠線。這就是第二節。
2. **尖峰脈衝 × MA → 中位數 → Hampel**：同一個尖峰，MA 攤成小方塊、中位數直接消失、Hampel 只換那一點。
3. **斜坡 + 雜訊 × EMA → α-β**：EMA 永遠落後一截，α-β 在斜坡上貼著綠線走。
4. **IMU × 互補濾波**：看橘線（純陀螺）越飄越遠、灰點（加速度計）很吵，藍線卻同時「不漂也不吵」。把 τ 拉到 5 s，就會看到漂移拉不回來。
5. **步階 × Biquad**：把 Q 從 0.707 拉到 2.5，步階後開始過衝、振鈴。
6. **步階 × One Euro**：β = 0 時跟 EMA 一樣慢；β 拉大後步階幾乎立刻跟上，但平坦段開始抖。

## 八、虛擬碼與實測數字

### MCU 版虛擬碼（C 風格，對照 `filters.py`）

```c
// ① EMA：1 個狀態，第一筆暖機
float ema_y; bool ema_init = false;
float ema_update(float x, float alpha) {
    if (!ema_init) { ema_y = x; ema_init = true; }
    else           { ema_y += alpha * (x - ema_y); }
    return ema_y;
}

// ② MA：環形緩衝 + 累加和（ADC 整數 → 用 int32 累加，沒有浮點漂移）
#define N 16
int16_t buf[N]; int32_t sum = 0; uint8_t idx = 0, count = 0;
int16_t ma_update(int16_t x) {
    if (count < N) count++; else sum -= buf[idx];   // 擠出最舊的
    buf[idx] = x; sum += x;
    idx = (idx + 1) % N;
    return (int16_t)(sum / count);                   // 暖機：除以目前點數
}

// ③ Biquad DF2T：2 個狀態
float z1 = 0, z2 = 0;
float biquad_update(float x) {
    float y = b0 * x + z1;
    z1 = b1 * x - a1 * y + z2;
    z2 = b2 * x - a2 * y;
    return y;
}

// ④ 互補濾波：1 個狀態
float angle_update(float gyro_rate, float accel_angle, float dt, float tau) {
    float alpha = tau / (tau + dt);
    angle = alpha * (angle + gyro_rate * dt) + (1.0f - alpha) * accel_angle;
    return angle;
}
```

|---|---|---|---|---|---|---|
| （原始量測） | 0.2504 | 0.0993 | 0.4277 | 0.1181 | 0 | 0 |

**怎麼讀這張表**：
- Hampel 在正弦上幾乎沒進步（0.2366）——它本來就不平滑白噪；但在尖峰上很好。

Hampel 抓到 100% 注入尖峰且誤判 2.3%、RateLimiter 每步變化絕不超過 max_rate·dt、
互補濾波 RMSE 同時小於加速度計、純陀螺與 EMA。

### 最後再濃縮成三句話
1. **設計思路**：先認雜訊——白噪用平均（MA / EMA / Biquad）、尖峰用排序（Median / Hampel）、漂移用融合（互補）、要跟得緊就加模型（Alpha-Beta / One Euro）。
2. **根本取捨**：因果濾波器越平滑就越延遲；更陡的濾波器、模型、自適應只是讓你少付一點延遲，不是免費。
3. **工程細節決定成敗**：fc/fs 單位、暖機初始化、整數溢位、控制迴路的相位裕度、先濾波再微分——公式對了但這些錯了，一樣上不了線。
